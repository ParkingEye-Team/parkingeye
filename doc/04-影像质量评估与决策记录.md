# 吉林一号影像质量评估与决策记录

> 评估日期：2026-09-07（质量评估）；车辆检测修正复测定稿 2026-09-09
> 评估对象：JL1KF01C（0.5m，2023-12-18，247km²）与 JL1GF03D06（0.75m，2023-11-26，405km²）
> 结论先行：**影像为真实分辨率、无造假，但冬季成像条件差（暗、低太阳角、长阴影、疑似雾霾）。车辆检测在修正复测下非"0 检出"而是"精度高、召回低"（检出即真车，约 80% 停车场车辆漏检，见 doc/05 第七节）；其余维度主体可推进，建议补申请夏季存档影像。**

## 一、用户观察

用户目视判读后认为"精度完全不够"。经程序化验证，该观察基本成立，但成因需澄清。

## 二、程序化验证结果

### 2.1 关键发现：JPG 快视图是 1/5 尺寸

- 包内 JPG 快视图：6326×6253
- TIF 原始数据：31634×31266
- **若双击 JPG 判读，等效看到的是 2.5m 分辨率，车辆只有 4×9 像素，必然"完全不够"**
- 正确判读方式：QGIS 打开 TIF，缩放到 1:1 像素级

### 2.2 TIF 为真实 0.5m（未上采样注水）

高频/低频能量比 0.016（清晰影像 >0.02，上采样糊图 <0.005）——数据是真实的 0.5m，不是插值放大产物。

### 2.3 但冬季成像条件差，车辆纹理微弱

| 指标 | 数值 | 说明 |
|------|------|------|
| 景整体亮度 | 44/255 | 偏暗 |
| 停车场区域亮度 | 31/255 | 非常暗 |
| 20 个抽样停车场车辆尺度纹理 | 中位数 6 个/场 | 车辆可见时应为 20–60 |
| 完全无车辆纹理的场地 | 7/20 | — |
| CLAHE 增强 | 无改善（更差） | 问题在信噪比而非对比度 |

成因分析：12 月 18 日 11:41 成像，成都纬度冬季太阳高度角约 30°，长阴影 + 盆地冬季雾霾（云量 0 不代表无霾），车辆与沥青路面对比度极低。

### 2.4 COCO 预训练 YOLO 检出 0 辆

预期内（训练域为地面视角照片），不作为影像质量证据，但确认必须使用航拍域模型。

## 三、对四个研究维度的影响

| 维度 | 是否受影响 | 说明 |
|------|-----------|------|
| ① 停车场区域识别（分割） | **基本不受影响** | 停车场地块是大面积均质灰色区域，0.5m 冬季影像 + 人工精标可训练；后续按停车场/地理区域划分并留独立测试区，避免空间泄漏 |
| ② 车辆/车位检测 | **受影响（召回不足，精度可信）** | 影像车辆纹理微弱是明显不利因素；修正复测（`res.obb`）表明 DOTA 权重检出即真车，但停车场内约 80% 车辆漏检（doc/05 第七节）；成都域微调目标为提升召回 |
| ③ 停车容量估计 | **不受影响（面积几何主线）** | 以可停车净面积 ÷ 布局综合占地为主，不依赖车辆识别；车辆检测作为当前占用辅助（可选） |
| ④ 空间评估（POI 融合） | **不受影响** | 依赖 POI/路网而非影像分辨率 |

**结论：四个维度中，②为"召回不足"（非失效），成都域微调可提升；其余维度主体可推进。**

## 四、决策与行动

### 4.1 车辆检测维度的替代训练路线（2026-09-07 增补，核心决策）

**两级训练策略，彻底绕开冬季吉林一号影像的缺陷：**

1. **第一级：DOTA v1.0 公开数据集预训练**（百度网盘可下，学术许可）。DOTA 的影像本身就部分来自 Google Earth（0.3–1m），small-vehicle 实例量大，让模型学会"俯视车辆长什么样"。
   - **版本决策（2026-09-07 修订）**：完整 DOTA-v2.0 约 130GB，其价值主要在打榜评估；本项目仅做预训练+成都微调，**只下 v1.0 训练集+验证集约 9GB 即可**（约 1869 张影像，small-vehicle 约 4 万实例，切 1024 块约 1.5 万训练块）。若 v2.0 网盘目录含独立小体积"标注文件"子目录可顺手转存（旧影像加密重标注），无则跳过。
   - 评估说明：因 v1.0 影像在 v2.0 中被重新标注（实例更多），如将来需在 v2.0 上评估，必须用 v2.0 标注，否则检出会被旧标注误判为误检；本项目用 v1.0 验证集自评+成都数据评估，不走官方测试服务器。
2. **第二级：Google Earth Pro 成都截图精标微调**。按采集规范（doc/08 第九节：垂直俯视、200–400 m 视角、命名 `场景_序号`、**不填坐标**；GE 影像版权归 Google，仅供内部标注/调试）。截图实际分辨率以比例尺/已知尺寸校准为准，**视角高度不能直接换算成 GSD**。标注组用 X-AnyLabeling Rotation 旋转框精标 30–50 张（车辆框，覆盖停车富集区）。
3. **域匹配优势**：DOTA 源影像 ≈ GE 截图 → 预训练与微调域间隙极小，这是本路线成立的关键。
4. **许可边界**：DOTA/xView/COWC 学术使用无虞；GE 影像版权归 Google，训练与内部验证可用，**对外演示/公开材料不展示原始截图**，系统底图用天地图（合规）。

**该路线与"补申请夏季影像"并行不悖**：夏季吉林一号到位后可直接在其上做最终推理与评估；未到位也不阻塞车辆检测模块。

### 4.2 其他维度与原行动项

1. **补申请夏季存档影像（首选，零成本）**：同一 AOI 申请 2023/2024 年 5–9 月存档数据。吉林一号星座百余颗卫星，夏季成都存档影像大概率存在。夏季太阳高度角高、植被覆盖、对比度好，同是 0.5m 可读性天壤之别。
2. **当前影像立即投入不受影响的维度**：OSM 弱标签 + 当前影像先训练停车场分割基线（本周原计划不变）。
3. **车辆检测模块暂缓实跑**，先在 DOTA 数据集上完成预训练（与影像无关，可并行）。
4. **若夏季影像仍不可用**（检查点：第 3 周），升级路径：
   - 0.3m Pléiades Neo 存档，25km² 最低订购约 ¥4000；
   - 或无人机自采试点区；
   - 或演示环节用 GE Pro 截图替代（内部使用）。
5. **降级预案**：若最终车辆检测精度不足，将该维度目标从"逐车框检"降级为"占用率估计"（纹理统计 + 密度回归），0.5m 下更现实。

### 6.2 重要修正：约 30% 死区是"条带形状"，不是冬季问题

夏季景与冬季景全图降采样统计：

| | 夏季 2024-08-25 | 冬季 2023-12-18 |
|---|---|---|
| 死区占比 | **29.7%** | **29.9%** |
| 有效区亮度 | 73.0 | 66.2 |
| 云量（元数据） | 0 | 0 |

**两景死区几乎一样**。原因是**推扫式（Line Push-Broom）卫星成像幅宽为斜条带**，转成矩形 GeoTIFF 后四角必然无数据——这是卫星影像固有条带形状，**与季节无关**。此前把"30% 死区"写入冬季影像问题清单属误判，特此修正。

### 6.3 两景覆盖区域不同（不能当作"同场地不同季节"）

夏季景覆盖成都东侧，冬季景覆盖西侧，**地理上基本不重叠**。此前人工标注的 63 个停车场都在冬季景范围内。因此：
- 两景**不能直接对比同一场地**；对同一 AOI 的夏季复拍仍需申请；
- 夏季景可独立用于"东部片区"的分割/检测验证与演示覆盖。

### 6.4 两景正式评估（2026-09-09，修正配置：检测 imgsz=1024/max_det=2000；分割 conf0.25）

**车辆检测**（同一模型/脚本，各自覆盖区内的 OSM 停车场窗口）：

| | 夏季（23 窗口） | 冬季（78 窗口） |
|---|---|---|
| 有检出（>0） | 23（100%） | 67（86%） |
| 检出总数 | 729 | 2719 |
| 每窗口中位 | 26 | 22 |
| 单窗口最多 | 122 | 323 |

**停车场分割（跨季泛化测试，模型在冬季影像上训练）**：

| | 夏季（23 窗口） | 冬季（78 窗口） |
|---|---|---|
| 有分割的窗口 | 6（26%） | 21（27%） |
| 分割实例数 | 7 | 29 |

**结论**：
1. **检测：两季表现基本相当**（中位 26 vs 22 辆/窗口），无"夏季显著更好"的证据——进一步说明此前"冬季不可用"的叙事被高估，季节不是检测的主因；修正配置下两季检出较 640 旧口径均提升 30–40%。
2. **分割：跨季无显著退化**（26% vs 27% 命中率），但**两季命中率都低（约 1/4）**——这是**训练数据规模问题**（仅 63 个人工多边形、覆盖场景有限），不是季节域问题，也不是过拟合到某一季。
3. 分割结果含误检可能（命中率仅统计"是否输出实例"，未经目视确认），需抽查叠加图（`data/infer/summer_eval/`）。

> 上述为 640 口径的初步数字；`doc/05` 7.1 节已发现推理分辨率/上限两处配置问题（修正后同窗口检出可增 2–3 倍），两景全图扫描需按 `imgsz=1024, max_det=2000` 重跑后再下定论。

### 6.5 检测策略含义（累积）

1. 车辆检测在 0.5m 影像上的可靠场景：**公路上/稀疏停车**（孤立、对比度高）；
2. **密集停车场内数车**在 0.5m 下接近物理极限（相邻车距仅 1–2px）——容量主线不依赖数车，此结论继续成立；
3. 推理必须用**原生分辨率 + 放宽 max_det**（已固化进 13 号脚本）；
4. 尺度鸿沟待验证：DOTA 训练车辆约 12×31px vs JL1 0.5m 车辆 4×9px（差 3 倍余），"尺度匹配重训"列为下一步实验候选。
