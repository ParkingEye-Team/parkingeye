## 项目定位与人力分工（SRTP，5 名大一学生 + AI）

**定位**：大学 SRTP 项目，交付**实际可运行的原型系统**（影像输入 → 识别 → 容量估计 → Web 看板全链路可演示）。因此优先级是：系统跑通可演示 > 精度指标 > 算法创新性。SRTP 结题所需的结题报告、演示视频、答辩 PPT 在第 7–8 周一并产出。

**分工原则**：AI 负责所有核心代码、训练管线和疑难问题；学生承担可并行、低门槛、成果可见的任务（标注、数据整理、前端内容、文档、测试），确保每个人都有明确产出可写进结题材料。硬件以训练日志为准：**RTX 5060 Laptop 8GB**。

## 范围决策（先定调，避免中途摇摆）

1. **暂不采购 0.3m 商业影像**。容量估计走几何规则路线（可停车净面积 ÷ 布局对应单车位综合占地；"空车位实时占用率"降级为试点展示项）。0.5m 影像下车位线通常不足 1 像素，逐车位线识别不在能力内，不影响四维目标成立。
2. **第 3 周设检查点**：若域适配后车辆检测效果确实不够，再启动 0.3m 采购（Pléiades Neo 25 km² 起，约 ¥4000），仍来得及。
3. **训练数据三板斧**：OSM 弱标签（已到手，311 个成都停车场多边形）+ 公开数据集（DOTA 车辆检测）+ 少量成都精标样本（X-AnyLabeling 旋转框，车辆框 + 地块多边形）。
4. **试点范围**：成都主城区 2–3 个典型片区（商圈/居住区/城乡结合部各一），不追求全市。

### 第 4 周：容量估计模块（交付主线）

> 容量估计定位为**不依赖车辆检测成功的面积几何主线**：基础容量走"可停车净面积 ÷ 布局单车位综合占地（含通道/转弯）"；车辆检测作为当前占用与布局辅助。输出必须含：面积、可停车净面积、布局类型、估计容量、当前可见车辆数（无检测时记"不可用"而非 0）、置信度/误差范围。

- [ ] 几何规则引擎：地块多边形 → 可停车带提取 → 按平行/垂直/斜列式推算理论容量
- [ ] 校准真值：**官方免费版 GE Pro 截图（内部参考，能辅助判读车位/布局）人工数真实车位数**，选 10–20 个分割圈出的停车场，对各排布类型校准单车位综合占地系数；OSM capacity 标签零星可用（311 个里仅 3 个有值）；有余力再实地数 3–5 个做交叉验证。校准集与测试集分开。
- [ ] 产出：容量推算 vs 真实容量 的误差报告（MAE/MAPE/平均偏差；这就是容量估计创新点的验证成果）
