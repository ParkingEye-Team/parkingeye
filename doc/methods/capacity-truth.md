# 容量真值采集操作说明（标注组一页版）

> 状态：current ｜ 最后更新：2026-10-18 ｜ 容量数字见 `doc/current/metrics.md`

> 目的：给 24 个候选停车场数出**真实车位数**，用于校准容量估计引擎并产出误差报告（核心创新点的验证闭环）。
> 工具：**Google Earth Pro 官方免费版**。仅内部使用；截图/坐标**不得**进入公开材料或系统底图。
> 工单：`data/capacity/truth_collection_blind.csv`（24 行，含 `split`：17 calib / 7 test；**不含模型估计值**，避免先入为主）。
> 预计耗时：每场地 5–10 分钟，完成 10–20 个约 2–3 小时。

---

## 一、准备（务必按新流程，防止覆盖）

1. 用 Excel 打开 `data/capacity/truth_collection_blind.csv`。
2. 确认列：`lot_id, lon, lat, area_m2, split, is_parking, facility_type, true_capacity, layout_true, notes, collected_by, date`。
3. `split` 已分配：**calib = 校准集**（用来调系数），**test = 测试集**（最终只评估一次，不要拿来调参）。优先做 calib。
4. 填写前**另存为新文件**：`data/capacity/truth_collection_filled_YYYYMMDD_<姓名>.csv`。
   - **绝不覆盖** `truth_collection_blind.csv`、`truth_collection_work_*.csv` 或他人已填文件；
   - 生成新文件是唯一允许的写法（2026-10-18 事故后定下的红线）。

## 二、逐场地操作（GE Pro）

1. 打开 GE Pro，在搜索框输入坐标，格式：`纬度, 经度`，例如 `30.718342, 103.993509`，回车定位。
2. 放大到能看清车位线（视角高度约 **100–300 m**；若影像模糊，换时间段影像或记录"不可判读"）。
3. **先判定"是不是停车场"（最重要）**：
   - `is_parking` 填 `是` / `否` / `不确定`。
   - `facility_type` 填（单选）：`公共停车场` / `配建停车场`（商场/小区/单位内部）/ `路侧停车` / `非正式空地停车` / `车辆堆场或报废场` / `其它`。
   - 判定为**否**的典型情况：报废车/车辆堆场、工地、物流货场、厂区空地、围合但无车位线且无实际停车行为的区域。
   - **关键判据**：如果场内车辆密集到"里面的车被外面的车围死、无法逐辆正常驶出"，大概率是**车辆堆场/报废场而非停车设施**——`is_parking=否`，`facility_type=车辆堆场或报废场`。
   - 填 `否` 时：`true_capacity` 填 `0`，`notes` 写清原因。
   - 填 `不确定` 时：`true_capacity` 留空，`notes` 说明疑点，由第二人复核。
   - 只有 `is_parking=是` 的场地才参与容量校准与误差评估；`否` 的场地会进入排除清单。
4. **数车位**：
   - 有清晰车位线：按格子数（斜列/垂直/平行都数）。
   - 无标线：按"能停一辆车的完整位置"数，**宁少勿多**，不要为凑数把通道、绿化、出入口算进去。
   - 只数**地面露天**车位；地下车库、立体车库、带顶棚车棚**不算**。
   - 路侧停车：按沿路实际可停放的车位数数，不按整条路面积折算。
5. 填写：
   - `true_capacity`：整数（主估计值）。
   - `layout_true`：`垂直式` / `平行式` / `斜列式` / `不规则`（混合时写主要类型，如"垂直式为主"，脚本会按前缀归一化）。
   - `notes`：不确定范围、树荫遮挡、边界不清、改扩建等（例："约 180–200，东侧树荫遮挡"）。
   - `collected_by`：姓名；`date`：采集日期（YYYY-MM-DD）。
6. 若场地与坐标偏差很大（例如坐标落在建筑上），在 `notes` 写"坐标偏移"，并跳过。

## 三、判定口径（避免争议）

| 情况 | 处理 |
|------|------|
| 车位线清晰 | 按线数格子 |
| 无车位线、地面划线模糊 | 按可停车位置数，宁少勿多 |
| 树荫/建筑遮挡 | 数可见部分 + 合理推测，`notes` 注明范围和遮挡程度 |
| 地下/立体/顶棚车库 | 不算 |
| 正在行驶的车 | 不算车位；只数停放位置 |
| 场地内有通道/绿化/出入口 | 不算车位 |
| 路侧/沿路条带 | 按实际可停车位置数；注意面积法容易把车道算进去，`notes` 注明 |
| 影像日期与卫星影像不同 | 容量按"设计车位数"数；若明显改扩建，`notes` 注明 |
| **车辆堆场/报废车场/工地/货场** | **`is_parking=否`，不计容量**；判据包括车辆被围死无法正常驶出 |

## 四、质量要求

- **不要看模型估计值**（盲采工单没有该列），先独立数完再比对。
- 每个场地至少自检一遍；抽查 20% 由第二人复核（差异 >20% 时第三人裁定）。
- test 集的 7 个场地**只数一次、不要反复调**，否则测试集会被"调参污染"。

## 五、交回与校准

1. 把填好的 CSV 另存为 `data/capacity/truth_collection_filled_YYYYMMDD_<姓名>.csv`（保留盲采文件原样）。
2. 运行校准（脚本会严格按 `split` 划分，缺 split 才随机 70/30）：

```bash
./.venv/Scripts/python.exe ml/scripts/22_capacity_calibrate.py \
  data/capacity/truth_collection_filled_YYYYMMDD_<姓名>.csv
```

3. 校准脚本会输出：
   - `data/capacity/calibration_report.json`（最新，覆盖前自动备份）；
   - `data/capacity/calibration_report_<run_id>.json`（本次快照）；
   - 按布局拟合的单车位综合占地系数、calib/test 的 MAE / MAPE / 平均偏差。
4. 若 `is_parking=否` 的地块较多，先把它们写入 `data/capacity/exclude_lots.csv`（列：`lot_id,reason`），重跑 18/21/24；排除项不计入容量总数与需求排名。

> 提醒 1：这份真值只用于**容量校准**，不用于车辆检测训练；两者口径不同（容量 ≠ 当前车辆数）。
>
> 提醒 2：当 OSM 边界明显大于分割识别区域（>1.5 倍）时，引擎会自动改用分割面积（`area_source=seg`），因此工单里的 `area_m2` 可能小于 OSM 多边形面积——这是为了排除堆场/空地混入，属预期行为。
>
> 提醒 3：2026-10-18 起，18 号脚本**默认不再生成真值工单**，也不会覆盖 blind 文件；如需额外工单，用 `--write-truth-sheet` 生成带时间戳的新文件。
