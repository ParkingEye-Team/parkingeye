# 项目难度与工程量评估（SRTP 内部参考 / 汇报材料）

> 撰写日期：2026-09-07
> 背景：5 名大一学生 + AI，工期两个月，目标交付实际可运行的原型系统（大学 SRTP 项目）
> 用途：立项 / 中期汇报引用，内部规划参考

---

## 一、总体难度判断

**对 5 名未接触过深度学习的大一学生：真实难度 7.5/10**（自行完成大概率超期）。

**有 AI 承担核心算法开发后：3.5/10**，两个月冲刺"能演示、能结题的原型系统"是现实目标。

关键认知：本项目的难点**不在深度学习理论**（训练、损失、评估指标对大一学生概念门槛不高），而在**工程链路**——环境搭建、数据格式转换、显存调试、GIS 融合、系统集成。这些恰恰是 AI 擅长、而新手最容易劝退的部分；学生的人力价值集中在数据采集、标注、文档与演示等环节。

## 二、模块级难度与工程量明细

| 模块 | 难度(1-5) | 已完工程量 | 剩余工程量 | 真实风险 |
|------|:---:|----------|-----------|---------|
| ① 数据获取 | ★★ | OSM 弱标签 311 个、吉林一号 2 景入库评估、DOTA 数据转换（4260+1220 切片） | 夏季影像申请、GE 成都截图采集 | **低**，但数据未到会卡进度 |
| ② 车辆检测 | ★★★★ | DOTA 预训练完成（mAP50=0.812）；已在成都冬季影像验证（检出 0，结论：影像问题非模型问题） | 成都目标影像（夏季/GE）上的微调与评估 | **中**——被影像质量卡住，非模型端 |
| ③ 停车场分割 | ★★★ | 工具链脚本就绪（切片/栅格化/标签）、311 弱标签入库 | 训练 + 评估（**尚未开始**） | 中——OSM 弱标签噪声较大 |
| ④ 容量估计 | ★★ | 无 | 几何规则引擎 + 已知容量停车场真值校准 | 低 |
| ⑤ 空间评估 | ★★ | 无 | 高德 POI 拉取 + 功能区划分 + 供需指标 | 低 |
| ⑥ Web 原型系统 | ★★★ | 无 | FastAPI 后端 + Leaflet 前端 + 图层/热力图 | **中**——学生组最可能卡壳处 |

**当前整体进度：约 20%**。数据底座与车辆检测预训练已完成，但四个研究维度尚无一个端到端跑通；③④⑤⑥ 均未开始。

## 四、当前最大风险与应对

### 风险 1：数据链路（时间黑洞，最高优先）

- **现状**：车辆检测被"缺可用的成都目标影像"卡住——冬季吉林一号影像对比度低，检出为 0；DOTA 预训练权重已就绪但无目标域数据可微调。
- **应对**：①申请夏季（5–9 月）吉林一号存档影像（零成本，同教育渠道）；②数据组采集 GE Pro 成都截图 30–50 张（0.15–0.3m，光照正常，与 DOTA 域接近）。两条并行，任一到位即可解锁微调。

### 风险 2：Web 系统集成（工程难点）

- **现状**：5 名学生无前端基础时，第 6 周将最吃力。
- **应对**：建议补一位略会 HTML/JS 的成员；第 2 周起即可让前端展示组成员自学 Leaflet（有 4 周缓冲）。

### 风险 3：范围蔓延

- **应对**：坚持"全链路可演示 > 精度指标"，容量估计走几何规则路线（不依赖车辆识别），空车位占用率降级为试点展示项。

## 五、成功标准（建议写入结题）

1. 系统能输入成都某片区影像 → 输出停车场地块 + 容量估计 + 供需热力图的**全链路演示**；
2. 分割 mIoU、检测 mAP 在试点片区达到可展示水平（数值待基线确立后定）；
3. 容量估计在 10–20 个已知真值停车场上的误差报告；
4. 结题报告 + 演示视频 + 答辩 PPT 齐备。
