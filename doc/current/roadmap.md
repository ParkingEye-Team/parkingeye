## 二、11 月期中报告（当前重点）

### 2.1 报告结构（建议 10–15 页）

1. **背景与目标**：停车资源摸底痛点；卫星影像 + AI 的可行性；明确“原型系统”定位。
2. **数据与前期工作**：4 景影像、311 OSM、25 张 GE 截图（12 张已标）、24 个 JL1 预标注窗口。
3. **技术路线**：一张流程图（影像 → 分割 → 矢量化 → 面积 → 容量 → POI → Web）。
4. **阶段性成果**：
   - 分割：512 val mask mAP50=0.804；1024=0.172（注明尺度差异）
   - 检测：DOTA 0.816、GE v2 0.856/v3 0.879；JL1 负迁移
   - 容量：24 地块/3456（区间 2689–4030，分割边界口径；来源敏感性 3993/4039）
   - 自检：2m 去重 335 辆（9.7%，仅下界），0 个“检出>容量”
   - POI：5812 个，需求指数 Top 3
5. **系统原型**：离线管线截图 + Web 静态地图（至少能点开一个地块看容量/需求）。
6. **问题与改进**：
   - 0.5m 分辨率不能逐车数清 → 面积法主线
   - 容量未校准 → 区间 + 真值采集重新开放
   - 路侧地块（seg_008）面积法偏高 → 人工复核布局
   - 分割 512/1024 尺度不一致、验证集小、空间泄漏
   - GE 截图版权边界
7. **后半程计划**：用本文第三节的 P2–P5。
8. **附录**：口径表、复现命令、审查修复记录。

### 2.2 PPT（10–12 页）

背景 2 页、路线 1 页、数据 1 页、成果 3 页（分割/容量/POI）、系统演示 2 页、问题与计划 2 页、致谢 1 页。

### 2.3 演示脚本（3 分钟）

1. 打开 Web 地图，说明试点 AOI（约 2km×2km）；
2. 点 seg_011：607 车位、区间、需求指数 100；
3. 点 seg_008：54 车位、需求指数 91.3、每车位需求 2.38，说明路侧不确定性；
4. 切 POI 图层，说明“需求代理 ≠ 真实供需”；
5. 主动说局限：未校准、0.5m 限制、POI 代理。

### 2.4 期中不要写的话

- “能数清每辆车”“容量精确到个位”“城市级全自动”“POI 反映真实供需”；
- 不要把 DOTA/GE 指标写成“成都精度”；
- 不要把 mask mAP 写成 mIoU/准确率。

## 五、决策点

1. **真值**：11 月能填多少填多少；填不完不阻塞期中，12 月继续。绝不再覆盖文件。
2. **Web**：静态 Leaflet 为必做；FastAPI 为加分项，不为了“像系统”过度工程。
3. **底图**：天地图（合规首选）或 OSM 瓦片（带 attribution）；**绝不用 GE 截图**。
4. **分割尺度**：容量主口径 1024（复现 24/3456）；512 作为验证集指标，不得混写。若要改 512，必须重跑并接受 26/3640 的差异。
5. **检测**：冻结 DOTA/GE 模型；不再扩 GE 标注；JL1 试点可选。
6. **影像**：新影像 24h 内入库；不为等影像推迟 Web/报告。
