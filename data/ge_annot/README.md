# GE 成都域截图库（车辆检测微调数据源）

> 用途：Google Earth 官方免费版截图，用于**车辆检测的成都域微调**（DOTA 权重在成都冬季影像上修正复测为"精度高、召回低"，约 80% 停车场车辆漏检——见 doc/05 第七节；成都域微调目标即提升召回）。
> 合规：仅内部算法调试/标注底图，不入系统底图、不入论文图片。
> 建立：2026-09-08。

## 目录约定

| 路径 | 内容 |
|------|------|
| `data/ge_annot/raw/` | 原始 GE 截图 + **X-AnyLabeling 标注 JSON（JSON 与图同目录，便于软件内查看/继续标）** |
| `data/ge_annot/README.md` | 本文件（上传清单 + 采集/标注规范） |
| `data/ge_yolo/` | 转换后的 YOLO-OBB 训练集（脚本 14 从 raw 读 JSON 自动生成） |

## 命名规范（重要：不填坐标）

**这批截图是训练素材，训练只认"图片 + 车辆框"，不需要经纬度**。所以文件名不用带坐标，写成：

```
场景_序号.png
```

示例：`商圈_01.png`、`医院_02.png`、`学校_01.png`、`居住区_03.png`。

- 场景用一个词概括（商圈/医院/学校/居住区/写字楼/枢纽…），序号两位起。
- 坐标等将来做地图落点时再单独补采，别让坐标拖慢采集。

## 标注规范（车辆检测：旋转框 OBB，单类 vehicle）

**工具**：X-AnyLabeling（免费，团队已在用）。

1. **打开图**：File → Open，选 `data/ge_annot/raw/` 下的 jpg。
2. **标注类别**：只标 `vehicle` 一类（标签名写 `vehicle`）。
3. **标注方式**：用**旋转框（Rotated Rect / Rotation）工具**沿车画框，框要贴合车头车尾方向（车是斜的就画斜框）。**不要用正矩形**——斜着停的车用正框会框进大片空地。转换脚本 `ml/scripts/14_ge_obb_to_yolo.py` 按四角点旋转框编写，两点正矩形会被跳过。
4. **标什么**：标**图里所有清晰可见的车**（含路边停放、路上行驶、工地内，**不限停车场内**）——训练检测器时样本越多样越会"认车"；将来"只数停车场内车辆"是在推理阶段用分割掩膜过滤，不是靠标注省略。
5. **框的松紧**：框紧贴车身（车顶外缘），不要含大圈空地或车影。**车影不要框进去**。
6. **存哪**：X-AnyLabeling 里标完一张**保存/导出 JSON**，JSON 会与图存在同一目录 `data/ge_annot/raw/`（**软件默认行为，别移走**——留在 raw 才能在软件里看到标注继续编辑）。`居民区_01.jpg` ↔ `居民区_01.json` 同名配对。
7. **每张标多少**：图里有多少清晰车就标多少（通常 10–100 辆），**不要只标一小部分就保存**。
8. **宁缺毋滥**：被树/建筑/阴影遮挡一半、模糊成一团的**不标**——样本多能稀释随机错标，但同一批图反复把遮挡物标成车会固化错误（尤其树多的居民区图，标完建议抽查最脏的几张）。

**导出后**：运行 `ml/scripts/14_ge_obb_to_yolo.py` 自动转成 YOLO-OBB 训练集（脚本从 `raw/` 读 JSON，图 <5 张时全进 train 不切 val；≥5 张按 80/20 划分）。**已实测验证**（2026-09-09）：公共场所_01.json（shape_type=rotation、points=4 角点、label=vehicle，45 框）转换成功 → `data/ge_yolo/train/`。格式要求：JSON 与图同目录放 `raw/`，每张图一个 JSON、与图同名。

## GE 截图采集规范（车辆检测微调素材）

1. **位置**：成都城区，优先有停车场的路段（商圈/医院/学校/居住区/写字楼/交通枢纽）。
2. **视角**：**垂直俯视**（"顶视图"，避免倾斜导致车辆变形）。若 GE 无纯顶视，用尽量小的倾斜角。
3. **高度**：200–400 m（约合 0.15–0.5 m/px，车辆 12–30 px 宽，适合检测与标注）。
4. **命名**：`场景_序号.png`，**不填坐标**。
5. **数量**：目标 30–50 张，覆盖不同停车场形态与光照。
6. **每张应含**：至少 1 个清晰可见的停车场地块（几辆到几十辆车）。
