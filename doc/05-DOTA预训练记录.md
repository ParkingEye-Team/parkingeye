## 一、数据转换

- 输入：DOTA v1.0 影像（train 1411 + val 458 张）+ v1.5 标注（加密超集，8 坐标旋转框）
- 只保留 small-vehicle / large-vehicle / car，合并为单一 vehicle 类
- 1024×1024 切片（重叠 200），多边形裁剪 + minAreaRect 转旋转框
- 产物：**train 4260 切片 / val 1220 切片**（脚本 `ml/scripts/04_dota_to_yolo_obb.py`）
- 类别分布确认：small-vehicle 5955、large-vehicle 1157（train 抽样 30 文件），车辆类占绝对主导

## 二、训练

- 模型：YOLO11n-OBB，imgsz 896，batch 4（8GB 显存安全值，初试 batch8@1024 触发 `bad allocation`）
- 进度：5 小时跑到 **epoch 27/80** 后人工停止（按此速度全程需约 15 小时，边际收益递减）
- 显存：常规 epoch 2.1G，高实例 batch 峰值 8.72G（顶格）
- 产物：`runs/obb/dota_vehicle_obb/weights/best.pt`（epoch 27）
- 日志：`runs_train_log.txt`

## 三、评估结果（分三组口径报告）

**训练轮次最佳值**（`runs/obb/dota_vehicle_obb/results.csv`，epoch 35，DOTA 验证集 1220 切片 / 57893 实例）：mAP50 = **0.8157**，mAP50-95 = **0.5295**，P = 0.782 / R = 0.756。

**训练末轮值**（results.csv，epoch 80）：mAP50 = **0.8120**，mAP50-95 = **0.5267**。

**训练后独立验证值**（`runs/obb/dota_vehicle_obb/weights/best.pt` 单独验证）：mAP50 = **0.808**，mAP50-95 = **0.518**，P = 0.772 / R = 0.747（`dota_resume_log.txt`）。

> 口径差异属正常（不同权重、验证时机、评估流程），摘要只可写"约 0.81 / 0.52–0.53"。`results.csv` 的 epoch 列为 1–80（不是从 0 计）。

**成都冬季影像初判（JL1KF01C 0.5m，2023-12；历史记录，已被第七节修正重测推翻）**：当时记录为检出 **0** 辆
- 当时归因：影像亮度低（停车场区域约 31/255）、对比度低；DOTA 训练影像与成都冬季影像域差异巨大
- **⚠️ 该"0 检出"来自读取 `res.boxes` 的脚本，OBB 结果应在 `res.obb`，结论作废**——修正重测为"精度高、召回低"，见第七节

## 四、结论与后续（2026-09-09 修订：第四节原"卡在数据端"表述部分保留，冬季归因移至第七节待重测）

1. 权重本身有效（DOTA 域 mAP50≈0.81），**留待成都目标影像 / GE 截图微调**后使用；
2. 成都目标影像到位后：直接在该权重上微调（而非重新预训练）；
3. GE 成都截图与 DOTA 训练域同源（Google Earth），域间隙预期较小，微调预期能获得更接近成都可用的检测器；截图实际分辨率以校准为准，不预设 GSD；
4. 车辆检测模块当前**卡在"成都域数据 + 可信评估"这一环**，不卡在 DOTA 域模型端。

## 五、经验教训

- RTX 5060 8GB 训练 OBB@1024：batch 4 + imgsz 896 是稳定配置；
- Ultralytics OBB 训练避免自定义 project（默认 runs/obb，叠加会嵌套）；
- Windows 下训练日志重定向到文件避免控制台缓冲丢失；
- 高实例 batch 会瞬间拉满显存，遇 `bad allocation` 降 batch 而非 imgsz。

## 七、成都冬季影像复测（2026-09-08初测 → 09-09 修正脚本 → 09-09 实测定稿）

### 初测（2026-09-08，结论作废）

- 用续训后的新 best 对 3 个人工确认有停车场的冬季 lot 区域（annot_aux lot_01/02/03，各 1024×1024）做原图 + CLAHE 两版推理，初测记录 conf 0.25/0.1/0.05 三档均 0 检出。
- **实现错误**：复测脚本读取 `res.boxes`，而 Ultralytics OBB 结果在 `res.obb`，初测"0 检出"是代码漏记旋转框，**结论作废**。初测还固定 conf 且未存叠加图。

### 修正重测（2026-09-09，`ml/scripts/13_recheck_chengdu_winter.py` 修正版：读 `res.obb`、跑三档 conf、存叠加图）

| lot（人工确认有停车场） | 原图 conf 0.25 | conf 0.10 | conf 0.05 | CLAHE conf 0.25 |
|---|---|---|---|---|
| lot_01（6.1ha） | **107** | 300截断 | 300截断 | 7 |
| lot_02（4.8ha） | **29** | 131 | 216 | 10 |
| lot_03（3.1ha） | **46** | 142 | 241 | 42 |

> conf 0.10/0.05 的 300 是 Ultralytics max_det 默认上限截断值，不代表恰好 300；conf 0.25 的 107/29/46 是未截断可信值。产物在 `data/infer/winter_recheck_v2/`（叠加图 + CSV）。

### 人工复核（标注组确认，2026-09-09）

对 conf 0.25 叠加图目视：**框出来的都是车（个别框到公路上行驶的车——那仍是车，推理阶段用停车场掩膜过滤即可，不算误检）**；但**停车场内约 80% 的车未被检出（召回低）**。

### 定稿结论（推翻初测"0 检出"）

1. **DOTA 权重在成都冬季影像上并非失效，而是"精度高、召回低"**：检出即真车（precision 可信），但漏掉约 80% 停车场车辆（recall 不足，影像弱信号 + 域差异共同导致）。
2. 此前"问题在影像不在模型"→"域差异"的判断，均基于作废的初测；**正确表述见上**——模型能看到部分车辆，但召回远不够用，这正是成都域微调要解决的。
3. **CLAHE 增强反而降低检出**（lot_01: 107→7，lot_02: 29→10）——对低信噪比冬季影像 CLAHE 有害，后续推理不用 CLAHE。
4. 12 号脚本（成都域微调前的复测工具）结论修正如上；**下一步目标明确：成都域微调以提升召回为主**。

- **对路线的含义**：车辆检测要在成都可用，需引入成都域目标影像微调（GE 截图 25 张已采 / 夏季吉林一号 / GF 渠道，见 doc/01 5.6/5.7）；DOTA 权重作为初始化，聚焦提升成都域召回。

### 7.1 推理配置修正（2026-09-09 晚，重要）

**发现**：此前全部复测/扫描都用了 Ultralytics 推理默认值，存在两处会系统性压低检出：

1. **imgsz 默认 640**：0.5m 影像整车仅约 4×9 像素，缩到 640 后再缩 1.6 倍 → 约 5px，接近可检测极限之下。实测同一密集窗口：imgsz 640 检出 64、**1024 检出 125**（原生尺寸最好；1280/1600 反而降，因插值模糊）。
2. **max_det 默认 300**：密集车场检出被截断（lot_01 在 1024 下恰好撞到 300）。

**修正后（imgsz=1024 原生、max_det=2000、conf 0.25）同一批冬季窗口**：

| 窗口 | 旧口径(640/300) | 修正后(1024/2000) |
|---|---|---|
| lot_01（6.1ha） | 107 | **344** |
| lot_02（4.8ha） | 29 | **51** |
| lot_03（3.1ha） | 46 | **65** |

**结论修正**：此前"召回低、约 80% 漏检"的评估**相当一部分是推理配置造成的假象**，不是影像极限。"检出即真车"的精度结论不变；召回的真实水平需在修正配置下重新目视判定（叠加图 `data/infer/winter_v5_maxdet/`）。密集车场在 0.5m 下的物理上限依然存在（车距 1–2px），但远好于旧记录。

**交叉验证**：GE 微调权重在相同修正配置下仍然大幅落后（14/8/0 vs DOTA 344/51/65），说明此前"GE 微调负迁移"的判断**不是配置假象**，结论保持。

**待办**：两景全图车辆扫描（夏季 565 / 冬季 1861，均为 640 口径）需按 1024/2000 重跑，得到修正基准；`ml/scripts/13_recheck_chengdu_winter.py` 已固化 `imgsz=1024, max_det=2000`。

### 7.2 等比放大实验（2026-09-09 晚，负结果）

**假设**：把影像等比放大，使车辆像素尺寸接近 DOTA 训练尺度（12×31px），能否提升检出？

**实验**：同一密集窗口（lot_01，原生车 4×9px），1×/2×/3× 放大 × Cubic/Lanczos 插值，推理 imgsz 随之 1024/2048/3072：

| 处理 | 检出数 |
|---|---|
| **1× 原生 1024** | **344** |
| 2× Cubic 2048 | 251 |
| 3× Cubic 3072 | 220 |
| 2× Lanczos 2048 | 287 |
| 3× Lanczos 3072 | 218 |

**结论：放大反而降检出（-15%~-36%），假设证伪。** 插值放大不产生真实细节——4px 的车放大成 12px 只是模糊团块，模型反而更易混淆。**推理端最优即原生分辨率**（1024 窗口 @ imgsz 1024），不再尝试放大；"尺度鸿沟"若要解决只能走训练端（用降采样的 DOTA 模拟 0.5m 尺度重训），列为候选实验而非当前主线。产物：`data/infer/upscale_test/`。

## 八、GE 成都域微调实验（2026-09-09）：出现负迁移，待多标图后重试

### 实验

- 数据：用户标注 4 张 GE 大图（公共场所 54 / 天府广场 124 / 学校 31 / 客运中心 253 = **462 框**），经 14 号（GE→YOLO-OBB）与 15 号（1024 切片）转成 **37 切片 / 554 框**。
- 训练：`ml/scripts/16_finetune_ge_obb.py`，DOTA best.pt 初始化，imgsz 1024 / batch 2，40 epoch。产物 `runs/obb/ge_finetune/weights/best.pt`。
- GE 训练集自身验证：P 0.823 / R 0.789 / mAP50 0.883 / mAP50-95 0.762（val=train 同源，仅作收敛监控，不代表泛化）。loss 平稳无过拟合迹象。

### 结果：冬季影像负迁移

同一批冬季吉林一号窗口，微调后 conf 0.25 检出：

| 窗口 | 微调前 DOTA best | GE 微调后 |
|---|---|---|
| lot_01 | 107 | **14** |
| lot_02 | 29 | **8** |
| lot_03 | 46 | **0** |

**微调非但没提升召回，反而大幅下降（负迁移）**——模型学到 GE 域风格后，丢掉了对冬季 0.5m 低对比影像的部分识别能力。

### 分析（待验证）

1. **训练数据太少**（4 张图/37 切片，单一 GE 底图风格）——模型过拟合到 GE 视觉域，尚无跨域鲁棒性。**首选怀疑**。
2. GE（Google 底图、光照好、亚米级）与吉林一号冬季（0.5m、暗、低对比）**成像域差异确实大**——即使都是"成都"，不能想当然认为可迁移。
3. 方向性疑问：纯 GE 微调也许根本不该指望迁移到吉林一号冬季；也许应 DOTA+GE **联合训练**，或 GE 微调只服务 GE/夏季影像域。

### 决策与下一步（2026-09-09）

- **用户选定：先多标 GE 图再重试**——排除"数据太少导致过拟合单一域"后再下结论。目标：标注 **10–15 张**（当前 4 张），重跑 14→15→16，再看冬季窗口检出。
- 若多标后仍负迁移 → 验证方向 2/3：尝试 DOTA+GE 联合训练，或接受"GE 模型服务 GE 域、DOTA 模型服务其他域"的域分离策略（GE 域模型仍可用于容量真值参考/夏季影像）。
- 同时，冬季影像的可用检测仍以 **DOTA best.pt** 为准（精度高、召回低，conf 0.25 检出 29–107）；GE 微调模型不用于冬季影像。
