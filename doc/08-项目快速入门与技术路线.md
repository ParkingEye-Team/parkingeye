## 一、这个项目到底在做什么（一句话）

给计算机看一张**城市的高清卫星照片**，让它自动找出**哪里有露天停车场、每个停车场大概能停多少车、哪些区域停车紧张**，最后把这些结果画在一张地图（看板）上给人看。

### 现实场景

成都某片区上空拍下一张 0.5 米分辨率卫星图。人眼可以分辨出：这块灰色空地是停车场、那块是工地；停车场里停了一排排车。项目目标就是让 AI 学会这种"看图"能力，替代人工逐个片区踏勘。

### 为什么难（相比普通照片识别）

| 挑战 | 说明 |
|------|------|
| 目标小 | 0.5m 影像里一辆车只有约 20×45 像素 |
| 俯瞰视角 | 车辆是"俯视"的，和日常拍照角度完全不同 |
| 干扰多 | 树冠遮挡、建筑物阴影、相似颜色路面（屋顶/工地/停车场都偏灰）|
| 数据少 | 带标注的城市卫星影像稀缺，且冬季影像光照差 |

## 二、技术路线总览（四个模块一条链路）

项目 = 一条"影像 → 结果"的处理流水线，中间串了四个研究模块：

```
卫星影像
   │
   ▼
【模块①】停车场区域识别  ──语义分割──► 地图上圈出每个停车场地块
   │
   ├───────────────────────────────►【模块③】容量估计
   │                                      │  用地块面积 ÷ 单车位占地
   ▼                                      ▼
【模块②】车辆/车位检测 ──目标检测──► 每个停车场里有多少车/空位
   │
   ▼
【模块④】空间评估 ──GIS 融合──► POI/路网叠加 → 哪些区域停车紧张
   │
   ▼
   Web 看板（Leaflet 地图）展示结果
```

> 编号说明：本入门把四个研究维度按"① 分割、② 检测、③ 容量、④ 空间"编号；doc/02 八周计划的模块编号以周计划表格为准，两处含义相同、编号方式略有出入。

| 模块 | AI 技术 | 解决的问题 | 输入→输出 |
|------|---------|-----------|----------|
| ① 停车场区域识别 | **语义分割** | "哪些像素是停车场地块" | 影像 → 逐像素分类（停车/非停车）|
| ② 车辆/车位检测 | **目标检测** | "车在哪、有多少" | 影像 → 每个车辆的框 |
| ③ 容量估计 | **几何规则**（非 AI）| "这地块能停多少车" | 地块多边形 → 容量数 |
| ④ 空间评估 | **GIS 空间分析**（非 AI）| "哪里停车紧张" | 容量 + POI → 供需热力图 |

### 两个"AI 模块"对应两种主流深度学习任务

- **语义分割**（模块①）：给每个像素贴标签。模型看一个区域，判断"这块属于停车场/道路/建筑/绿化…"。
- **目标检测**（模块②）：在图上画框标出物体。模型输出"这里有一辆车"，用旋转框贴合车的方向。

### 两条模型线：各管一件事，在容量估计里合流

最容易混淆的一点：**模块① 和模块② 不是同一个任务，谁也替代不了谁**。

- **分割模型输出的是一片"区域"**（这块地是停车场，边界到哪）。它回答"哪里能停车"。
- **检测模型输出的是一辆辆"车"**（每辆车一个旋转框）。它回答"现在停了几辆"。

容量估计（模块③）就是把两条线的结果拼起来：
先让分割模型圈出"哪里有停车场"，再让检测模型数出"这片区域里停了多少车"，最后用几何规则（区域面积、车辆朝向推断车位排布）推算设计容量。

所以两个模型的训练数据来源天然不同、互不重叠：

| 模型线 | 负责目标 | 数据从哪来 | 为什么不能互相借数据 |
|--------|---------|-----------|---------------------|
| 分割线（停车场区域） | 模块①、③的一半 | OSM 弱标签 + **人工标注 parking** | DOTA 只有"车"，**没有"停车场范围"这类区域标签** |
| 检测线（车辆） | 模块②、③的另一半 | **DOTA 公开集**（白拿的预训练能力） | 人工标 parking 不含车辆框，与检测训练无关 |

**换个说法**：你人工标注的 parking 多边形，喂的是分割线，它补的正是 DOTA 给不了的那半边。两条线各有各的弹药，不重复、也不缺。

## 三、为什么需要"标注数据"（项目最关键的概念）

**深度学习模型 = 从例子中学习的程序**。它不看任何规则手册，而是看海量"输入 + 正确答案"对，自己总结规律。

所以训练前必须准备：`影像图片 + 对应的答案`。

- 模块①（分割）的"答案"是：**把停车场轮廓涂成白色、其余黑色**的掩膜图（mask）；
- 模块②（检测）的"答案"是：**图上每个车画一个框**。

你刚用 X-AnyLabeling 做的辅助图标注，就是给模块①准备"答案"（勾勒停车场轮廓）。已采集 50 张辅助图，其中 49 张有有效标注 JSON、共 63 个 parking 多边形（第 15 张暂缺 JSON，不计入有效标注）。标注质量直接决定模型学得好不好——**AI 项目里"标注"是最重要也最花人力的环节**。

### 我们项目的数据来源（四种，可靠性递增）

| 数据 | 来源 | 用途 | 可靠性 |
|------|------|------|--------|
| OSM 停车场多边形 | 开放街道地图（网友标注） | 分割初探 | ★★ 漏标多 |
| DOTA 公开数据集 | 武大（含 Google Earth 车辆标注） | 车辆检测预训练 | ★★★★ |
| **人工精标（X-AnyLabeling）** | **我们团队刚做** | 分割训练 | ★★★★★ |
| GE 截图/夏季影像 | Google Earth / 吉林一号 | 域适配微调 | ★★★ |

> 已完成的辅助图标注 = 49 张有效 JSON、63 个高质量停车场轮廓，是目前**最可靠**的成都本地数据。
>
> **这批标注为什么只标 parking、不标车？** 因为它是给分割线用的：分割模型只需要"这块地是不是停车场"，不需要也不关心里面有几辆车。0.5m 影像下车位标线通常不足一个像素，肉眼难以稳定判读，所以"逐车位线标注"在能力边界外——现实做法是"区域面积 + 车辆数 → 推算容量"，而不是直接标车位线。
>
> 那 DOTA 的红利（检测线）怎么在成都兑现？等成都目标影像到手后，先拿 DOTA 预训练好的检测器去成都影像上测——如果迁移失败，再在若干张成都影像上标一批车（**旋转框**，见第九节），**用 DOTA 权重自动预标注 + 人工纠正**，把标注量压到最低。这才是吃 DOTA 红利最划算的时机。

## 四、模型是怎么"学会"的（训练 5 步走）

以车辆检测为例（我们已跑通的模块）：

1. **准备数据**：图片 + 每张图的答案（框）。我们已从 DOTA 切出 4260 张训练块。
2. **选模型**：YOLO11n（目标检测领域最主流的开源模型之一）。"n" 是 nano 小版本，适合 8GB 显卡。
3. **前向传播**：模型看一张图，输出它的"猜测"（一堆框 + 置信度）。
4. **算损失**：把猜测和正确答案比较，算出一个"错得有多离谱"的分数（loss）。例如模型没框出车 → loss 高。
5. **反向传播**：根据 loss 微调模型内部数百万个"旋钮"（参数），让下次猜得更准。

重复 3→4→5 成千上万次（一个来回叫一个 **epoch**），模型越猜越准。DOTA 车辆检测已跑完 80 epoch：训练最佳轮次（epoch 35）mAP50≈0.816、mAP50-95≈0.530；末轮与独立复验口径见 doc/05 第三节。**注意：这是 DOTA 验证集指标，不是成都精度；"0.81"也不是 81% 准确率，而是检测综合指标。**

```
训练前： 模型乱猜（loss 高）  ──►  训练 N 个 epoch  ──►  模型会认车（loss 低）
```

### 关键术语：预训练与微调

- **预训练**：先用别人的大数据（DOTA，约 5 万辆车）让模型学会"俯视车辆长什么样"。通用能力。
- **微调**：再用自己的小数据（成都）让模型适应本地风格（比如成都的车、成都的路面）。专项能力。

类比：预训练是"上完大学的通识课"，微调是"入职后的岗位培训"。

## 五、为什么车辆检测在成都冬季影像上先不理想（本项目踩过的大坑）

我们申请的两景吉林一号影像拍于 **11 月底和 12 月**。测试发现：

- 影像约 30% 区域存在**纯黑死区**（无数据，可能源于云掩膜/拼接缝，以实际掩膜统计为准）；
- 车辆区域整体偏暗、**对比度有限**（成都冬季太阳高度角低 + 雾霾是可能因素）。

**实测结论（2026-09-09，修正脚本后）**：DOTA 车辆检测在成都冬季影像上**不是 0 检出**——对人工确认有停车场的 3 块区域，conf 0.25 下检出 29–107 辆；人工复核确认"框出来的都是车"。真正的短板是**召回低**：停车场内约 80% 的车辆没被检出（影像弱信号 + DOTA 域到成都冬季域的差异共同导致）。早期"0 检出"是复测脚本读错字段（`res.boxes` 而非 `res.obb`）造成的假象（细节见 doc/05 第七节）。

**教训**：①遥感 AI 里"有影像"≠"影像能用"，成像条件（光照/季节/雾霾）确实关键；②**评估脚本本身也可能错**——跨域结论前先确认代码读对结果字段、保存可视化复核。这也正是我们转向人工精标（人眼在增强图上能认出停车场）+ 成都域微调的原因。

## 七、术语表

### A. 数据与标注
| 术语 | 含义 |
|------|------|
| **像素** | 构成数字图像的最小点。一张 1024×1024 图 = 约 105 万像素 |
| **分辨率 / GSD** | 一个像素代表地面的尺寸。0.5m = 每像素对应 0.5m×0.5m 地面；越小越清晰 |
| **标注 / Annotation** | 给数据附上"正确答案"，如给车画框、给停车场描轮廓 |
| **掩膜 / Mask** | 与影像同尺寸的"答案图"，白色=目标，黑色=背景（分割的答案形式）|
| **多边形 / Polygon** | 一串顶点围成的封闭区域，用于精确标注不规则地块 |
| **标签 / Label** | 给目标起的名字，如"parking"、"car" |
| **数据集 / Dataset** | 一组"图片+标注"的集合，分训练/验证/测试集 |
| **GeoJSON / SHP** | 带地理坐标的矢量数据格式（存多边形、点、线）|
| **GeoTIFF** | 带地理坐标的影像文件格式（存卫星图）|

### B. 深度学习
| 术语 | 含义 |
|------|------|
| **深度学习** | 用多层神经网络从数据中自动学习特征的方法 |
| **神经网络** | 由大量参数组成的"函数"，输入图片输出预测 |
| **参数 / 权重** | 网络内部可学习的数字，训练就是调这些数字 |
| **模型 / Model** | 训练好的神经网络（一个文件，如 best.pt）|
| **训练 / Training** | 用数据反复调整参数让预测变准的过程 |
| **推理 / Inference** | 用训练好的模型对新图片做预测（不再调整）|
| **前向传播** | 图片经过网络层层计算得到预测结果 |
| **反向传播** | 根据预测误差反向调整网络参数 |
| **损失 / Loss** | 预测与答案差距的量化分数，训练就是最小化它 |
| **epoch** | 把整个训练集完整过一遍叫一个 epoch |
| **batch** | 一次喂给模型的图片数（受显存限制）|
| **batch size** | 每批图片数量，越大越快但越吃显存 |
| **学习率 / lr** | 每次调整参数的步长 |
| **过拟合** | 模型背下训练集却不会泛化（新图表现差）|
| **预训练** | 在大数据上先训练，获得通用能力 |
| **微调 / Fine-tune** | 在预训练基础上用小数据继续训练，适配特定任务 |
| **权重文件** | 训练结果保存的文件（.pt），加载即可推理 |

### C. 任务类型与模型
| 术语 | 含义 |
|------|------|
| **目标检测** | 任务：找出图中物体并画框（车、人等）|
| **语义分割** | 任务：给每个像素分类（这个像素是停车场/道路…）|
| **实例分割** | 任务：分割 + 区分每个个体（这辆车和那辆车分开）|
| **旋转框 / OBB** | 可旋转的检测框，贴合俯视图里倾斜的车辆 |
| **YOLO** | 最流行的实时目标检测模型系列（Ultralytics 实现）|
| **YOLO11n / YOLOv8** | YOLO 具体版本，n= nano 轻量版 |
| **SegFormer / DeepLabV3+** | 语义分割常用模型（本项目未选用，采用 YOLO11n-seg 实例分割）|
| **SAM** | Meta 的分割大模型，可辅助标注 |
| **Transformer** | 一种神经网络结构（近年主流）|

### D. 评估指标
| 术语 | 含义 |
|------|------|
| **IoU** | 预测框与真实框的重叠度（交集/并集），0–1 |
| **mIoU** | 分割任务的平均 IoU，越高越好（我们追求 >0.6）|
| **mAP** | 检测任务综合指标（非"准确率"；本 DOTA 模型训练最佳 mAP50≈0.816，属 DOTA 域，非成都精度）|
| **mAP50** | IoU>0.5 算对的 mAP |
| **精确率 Precision** | 检出的东西里有多少是对的 |
| **召回率 Recall** | 真实目标里有多少被检出来了 |
| **混淆矩阵** | 显示"预测 vs 真实"的表格，看错在哪类 |

### E. 遥感与 GIS
| 术语 | 含义 |
|------|------|
| **卫星影像** | 卫星从太空拍摄的地球照片 |
| **正射影像** | 消除透视畸变、地理精确的影像 |
| **坐标系 / CRS** | 描述地球位置的系统（如 WGS84 经纬度、UTM 米制）|
| **投影** | 把球面坐标转到平面坐标的方法 |
| **EPSG** | 坐标系的标准编号（32648=成都用的 UTM 48N）|
| **瓦片 / Tile** | 地图切成的小方块，按需加载（Leaflet 用）|
| **POI** | 兴趣点（Point of Interest）：商场、小区、写字楼等 |
| **路网** | 道路的矢量数据 |
| **GSD** | 见上方"分辨率"，航空遥感常用 |
| **云掩膜** | 影像中云/无数据区域的标记 |
| **GIS** | 地理信息系统，处理空间数据的技术 |

### F. 工具与流程

| **FP16 / 混合精度** | 用半精度计算省显存、提速 |
| **Ultralytics** | YOLO 的 Python 库，训练/推理一条龙 |
| **PyTorch** | 深度学习主框架（我们基于它）|
| **切片 / Tiling** | 把大图切成小块再喂模型（处理超大卫星图）|
| **切片重叠 / Overlap** | 相邻切片重叠部分，避免目标被切碎 |
| **OpenCV (cv2)** | 图像处理库 |

| **QGIS** | 免费 GIS 桌面软件（看/标空间数据）|

| **OSM / OpenStreetMap** | 开放街道地图（众包地图数据源）|

| **FastAPI** | Python Web 后端框架（做系统服务）|
| **Leaflet / MapLibre** | 网页地图前端库（做看板）|

## 九、GE 截图采集操作手册（车辆检测微调素材）

> 目的：用 Google Earth 官方免费版截取成都城区高清图，作为**车辆检测的成都域微调数据**（DOTA 权重在成都冬季影像上修正复测为"精度高、召回低"、约 80% 停车场车辆漏检——见 doc/05 第七节，需成都域影像微调提升召回）。
> 合规：**仅内部算法调试与标注底图**，不进系统底图、不进论文图片（版权归 Google）。不用破解版。

### 用什么软件

- **Google Earth Pro 官方免费版**（不是破解版，官网可下，免费）。

### 一步一步怎么截

1. **打开 GE Pro**，在搜索框输入目标地点（如"成都 春熙路""XX 医院"），回车定位。
2. **找停车场**：优先商圈 / 医院 / 学校 / 居住区 / 写字楼 / 交通枢纽附近，这些地方有集中停车的地块。要找"一片停着很多车的地方"。
3. **切到垂直俯视**：让视角正对地面往下看（导航罗盘上点"N"上方那个箭头，或按住 Ctrl 拖动调整），**避免斜着看**——倾斜会让车变形，影响标注和训练。
4. **调高度**：把视角高度调到 **200–400 米**（画面右下角状态栏会显示"视角高度 XXX 米"）。这个高度通常能看清车、也不会太近。**注意：视角高度不等于影像真实分辨率**，实际每像素地面尺寸以后续比例尺/已知尺寸校准为准，截取时尽量固定缩放级别和构图。
5. **构图**：画面应尽量**只含停车场及紧邻区域**，一张图至少要有 1 个清晰停车场地块、几辆到几十辆车。
6. **截图并命名**：按截图键（或文件→保存图像）存为 PNG，**文件名写成 `场景_序号.png`**（如 `商圈_01.png`、`医院_02.png`）。**不需要填坐标**——这批图是训练素材，YOLO 训练只认图片+框，不看经纬度；坐标等将来要做地图落点时再单独处理。
7. **上传**：把 PNG 放进项目目录 `data/ge_annot/raw/`，并在 `data/ge_annot/README.md` 的清单里加一行（或告诉 AI 帮你登记）。

### 采集标准速查

| 项 | 要求 |
|----|------|
| 地点 | 成都城区，有集中停车的地块 |
| 视角 | **垂直俯视**（顶视图，不倾斜）|
| 高度 | 200–400 m（尽量固定缩放级别；不按视角高度换算真实 GSD）|
| 画面内容 | 至少 1 个清晰停车场，几辆到几十辆车 |
| 命名 | `场景_序号.png`（如 `商圈_01.png`），**不填坐标** |
| 数量目标 | 30–50 张，覆盖不同停车场形态（商圈/医院/学校/居住区/写字楼/枢纽）|
| 存放 | `data/ge_annot/raw/` |

### 截完图之后会发生什么

这批图会走和"辅助图标注"一样的流程：**GE 截图 → X-AnyLabeling 标车（`Rotation` 旋转框，类名 vehicle）→ 转 YOLO-OBB 格式 → 在 DOTA 预训练权重上微调**，得到一个"成都可用"的车辆检测器。这是当前打通车辆检测成都域的关键一步。

> **标注格式要求**：转换脚本 `ml/scripts/14_ge_obb_to_yolo.py` 目前按**四角点旋转框**编写，两点正矩形会被跳过；导出的 JSON 由 X-AnyLabeling 存在 `data/ge_annot/raw/`（与图同目录，**别移走**，方便软件内查看续标）。**建议先标 1 张并成功转换后，再批量标注。**

> **为什么不用填坐标？** 训练只认"图片 + 车辆框（图上像素）"，不需要经纬度。坐标只在地图落点/跨图源对齐时才需要，那是后话，届时再单独补采，别让坐标拖慢现在的采集。
